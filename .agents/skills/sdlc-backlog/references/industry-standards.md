# Backlog Industry Standards

This skill is designed to produce backlog artefacts that align to widely adopted agile delivery practices.

## Scrum Guide

The Scrum Guide by Ken Schwaber and Jeff Sutherland defines the Product Backlog as an emergent, ordered list of work required to improve a product. The backlog produced by this skill should therefore be transparent, ordered, and clearly valuable.

Reference: https://www.scrum.org/resources/scrum-guide

## SAFe

Scaled Agile Framework guidance emphasises traceability from epics to features, enablers, and delivery outcomes. For larger systems, architecture-driven backlog generation should preserve capability boundaries, dependencies, and planning context.

Reference: https://scaledagileframework.com/

## INVEST

User stories should satisfy the INVEST heuristic:

- Independent
- Negotiable
- Valuable
- Estimable
- Small
- Testable

## Gherkin / Cucumber

Acceptance criteria should be expressed in executable Given / When / Then form to enable BDD-style review and automation.

Reference: https://cucumber.io/docs/gherkin/

## Mike Cohn Story Format

Use the canonical story sentence:

`As a [persona], I want [capability] so that [benefit]`

Reference: Mike Cohn, *User Stories Applied*.
