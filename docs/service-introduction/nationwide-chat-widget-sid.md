## Executive Summary

Nationwide Chat Widget is the Nationwide-branded web front end that embeds the Amazon Connect hosted chat capability into Nationwide digital journeys. The component mirrors the Meridian pattern at a technical level but presents a distinct visual identity, content structure, and deployment profile suitable for Nationwide's member-facing experience.

Repository analysis shows a React and Vite front end with a dedicated `vite.config.js`, a Nationwide-styled `App.jsx`, and a `ConnectChatWidget.jsx` component that attaches Amazon Connect event hooks and uses a `MutationObserver` to normalise participant labels. Public assets include a Nationwide logo image, and the page design reproduces a more content-rich retail-banking landing experience with product-navigation, award badges, and product-category tiles.

The service is Tier 1 because it is intended as a primary digital chat entry point for a major retail financial institution. It must therefore be governed through the same operational rigor as any customer-facing service: controlled release management, security-header assurance, approved-origin governance, incident support, disaster recovery planning, and clear accountability across brand, platform, and contact-centre teams.

This SID formally onboards the service into the ARIA platform landscape as a white-labelled but independently governed front-end channel. It documents the service contract, support expectations, and operational dependencies required for Nationwide production use.

## Service Scope

### In-Scope

- The React and Vite application in `nationwide_chat_widget/` including `App.jsx`, `main.jsx`, styling, and public assets.
- Hosted widget bootstrap and configuration defined in `index.html`.
- Client-side participant label handling and Connect event hooks in `src/components/ConnectChatWidget.jsx`.
- Nationwide-specific branding, logo treatment, product navigation, hero, badges, and product cards.
- Static production build generation to `dist/` and deployment to S3 + CloudFront.
- Origin and header controls required to allow the hosted widget to initialise safely on Nationwide domains.
- Customer chat initiation, messaging, transfer, and disconnect interactions as exposed through the hosted widget runtime.

### Out-of-Scope

- Back-end AI orchestration, banking tool execution, and customer authentication logic downstream of the channel.
- Connect queue design, workforce management, and advisor desktop applications.
- Nationwide core banking systems, CRM systems, and records management platforms.
- Analytics tagging strategy outside what is explicitly connected to widget health and service observability.
- Regulatory control ownership beyond the channel-specific implementation of those controls.
- Separate bespoke backend services for the widget; this component intentionally remains a static front-end experience.

### Service Boundaries

The service boundary begins at Nationwide's web delivery layer and ends at the hosted Amazon Connect runtime. The browser owns the rendered shell and light DOM presentation behaviour, while Amazon Connect owns session management, message exchange, transcript rendering, and participant-state behaviour.

The service boundary also excludes privileged business processing. If the customer journey requires identity proof, sensitive banking actions, or escalation logic, those capabilities are executed in downstream platform services. This boundary is important because it keeps the Nationwide front end operationally light while still treating it as a critical customer channel.


## Technical Architecture

### Overview

The Nationwide widget architecture mirrors the Meridian technical pattern but with its own branded user interface and configuration defaults. `vite.config.js` sets dedicated dev and preview ports on `4001`, `App.jsx` renders the Nationwide landing-page shell, and `ConnectChatWidget.jsx` applies participant-name normalisation plus event-hook registration for connection lifecycle events.

The implementation uses public assets such as `nationwide-logo.png`, custom SVG product icons embedded in JSX, and a strong blue-and-red palette defined in CSS variables. The page is more content-dense than Meridian's shell, reflecting Nationwide's broader member-facing product-discovery posture while still deferring the actual chat session runtime to the hosted Connect widget.

## Security & Compliance

### Security Classification

The document classification is Internal, while the delivered service is a public, customer-facing ingress point into regulated banking interactions. The service must therefore be operated as a hardened web-entry surface with explicit control over dependencies, origins, and data minimisation.

### AuthN/AuthZ

- The channel entry point may be publicly reachable, but privileged banking actions are authorised only in downstream services.
- No AWS secrets, customer credentials, or reusable confidential tokens may be embedded in shipped JavaScript, HTML, or public assets.
- Browser-side contact attributes must be restricted to minimal session context and localisation hints.
- Approved-origin governance in Amazon Connect is a mandatory control for where the hosted widget may execute.
- Any authenticated customer context used later in the journey must be obtained through platform-owned identity and KBA controls, not the widget shell itself.

### Data Classification

| Data Type | Classification | Handling Expectation |
| --- | --- | --- |
| Static UI content | Public | May be served externally but remains release-controlled |
| Brand assets | Public / controlled branding | Protected through asset and design governance |
| Session metadata | Confidential operational data | Minimise and govern carefully |
| Chat conversation content | Confidential banking interaction data | Handled downstream by Connect and ARIA controls |
| Authentication or profile context | Regulated confidential data | Must not be stored persistently in the browser shell |

### Regulatory Requirements

- HTTPS-only service exposure with approved TLS policy.
- Strict origin allow-listing and controlled response headers for hosted widget compatibility.
- GDPR-aligned data minimisation for browser-side processing and metadata injection.
- FCA-aligned operational resilience and customer communication expectations for digital channels.
- Third-party script governance appropriate for a regulated financial brand.
- Alignment to platform-wide audit, monitoring, and incident-management controls even where the browser itself stores little persistent state.

The most important control principle is the same as for Meridian: keep sensitive logic out of the browser, and keep the browser channel simple, observable, and tightly governed. This reduces attack surface while allowing brand flexibility at the presentation layer.


## Capacity & Scalability

### Current Capacity

Nationwide Chat Widget is primarily constrained by CDN delivery and Amazon Connect chat-session quotas rather than by any application-server footprint. The front end is static, lightweight, and browser-executed, which makes it operationally inexpensive to scale for read traffic. Conversation scale must instead be planned through the shared ARIA platform and Connect service quotas.

| Capacity Dimension | Current Characteristic | Planning Implication |
| --- | --- | --- |
| Static delivery | CloudFront + S3 pattern | Elastic web serving under high browse traffic |
| Bundle runtime | Browser-executed React app | No dedicated compute tier to autoscale |
| Chat concurrency | Managed by Amazon Connect and downstream platform services | Quota and advisor-capacity planning required |
| Responsive design | One codebase across desktop and mobile | Need multi-device non-functional testing |
| Brand content density | More page content than Meridian shell | Monitor payload weight and layout stability |

### Scaling Approach

- Use CloudFront edge caching and versioned assets to absorb browse-volume spikes.
- Monitor and manage Connect concurrency, routing, and advisor availability for real chat load.
- Optimise bundle size and image handling so brand richness does not degrade time to widget readiness.
- Preserve the shared hosted-widget pattern to avoid fragmenting operational support across brands.
- Rehearse brand-domain onboarding steps, especially origin allow-listing and security-header validation.

### Known Limits

## Disaster Recovery & Business Continuity

### DR Strategy

The Nationwide widget follows the same low-state recovery pattern as Meridian. Static assets can be rebuilt and republished quickly, while customer conversation state is retained in downstream services rather than in the front-end shell. This simplifies channel restoration and supports clean rollback to a previous known-good version.

### RTO/RPO Targets

| Measure | Target | Rationale |
| --- | --- | --- |
| RTO | 4 hours | Tier 1 channel restoration objective |
| RPO | 1 hour | Protects deploy metadata and configuration state for rapid recovery |

### Failover Approach

1. Promote the last known-good static build or rebuild the front end from source under change control.
2. Publish recovery artefacts to the primary or standby S3 origin and refresh CloudFront behaviour.
3. Validate that Nationwide production domains remain present in the Connect approved-origin allowlist.
4. Run live browser checks for desktop and mobile launch, first response, and advisor transfer.
5. If downstream platform health is impaired, remove or suppress the chat entry point and route customers to resilient alternative channels.

Business continuity must consider customer trust as well as technical restoration. If the front-end shell is healthy but the conversation path is not, the correct decision may be to withdraw the chat entry point temporarily rather than leave a degraded experience visible on a financial-services homepage.
